1產品定位與基本規則

  • 漫畫館是 JS GAME 遊戲官網同網域下的子路徑（例 /comic），不是子網域，登入狀態與平台幣因此與遊戲站共用。
  • 漫畫館與遊戲站是兩個平行世界，各有自己的底部導覽，彼此的入口要對稱。
  • 帳戶層沿用遊戲、內容層漫畫自訂：帳號、平台幣、充值、客服共用；目錄、購買、書櫃、閱讀是漫畫館自己的。
  • 作品一律以 workId 為識別。書櫃、收藏、進度、通知深連結、卡片點擊都用 ID，不可用作品名當 key。
  • 線上串流閱讀、不提供付費內容下載，所以書櫃沒有下載鈕。App 體驗用 PWA。
  • 內容型態以日系翻頁漫畫為主（右翻、支援見開き跨頁、相鄰頁預載），非條漫直捲。

1.1 商業模式

  • 第一版以單本買斷為主，連載為次要。
  • 三種商品型態：單卷單行本 ／ 多卷單行本 ／ 每話連載。多卷＝比照連載、單位從「話」換成「冊」是核心原則。
  • 價格一律標單位：單本 ／ 每冊 ／ 每話；多卷各冊不同價時加「起」。
  • 連載購買分兩層：下一話一鍵解鎖 ＋ 整部購買（折扣）。不做勾選式多選，也不做購物車。
  • 每部作品都有免費試閱（前幾頁或前幾話），所以免費試閱不是促銷條件，不做角標、也不做篩選維度。
  • 頁面架構以作品為單位，不是以冊為單位；書櫃同樣一個作品一格。

1.2 購買範圍 scope

五種購買範圍會一路貫穿定價、優惠券適用判斷、訂單與權益開通，前端每一個購買動作都要帶：

scope對應購買行為介面文字
single單卷單行本買斷單本買斷
vol多卷作品的第 N 冊單冊
set整套購買／解鎖剩餘冊整套
ch連載的第 N 話單話
bundle整部購買／解鎖剩餘話整部

1.3 營運型態開關

全站有一個營運型態開關：含連載 ／ 只有單行本。切到「只有單行本」時三處同時隱藏，且已選的條件會被清掉：

  • 排行榜的分類切換（綜合／單行本／連載）
  • 找漫畫的「類型」篩選整組
  • 書櫃的「型態」篩選（收藏分頁因此一組都不剩，連篩選鈕都不出現）

2.4 收藏入口

位置有沒有愛心
找漫畫列表卡（封面右上）、作品介紹頁、書櫃收藏分頁✅ 有

首頁的小卡（熱門排行、新刊、特價、話題標籤）、排行榜頁❌ 沒有
  • 收藏只有一份真相，以作品 ID 為 key；任一處收藏或取消，其他入口立刻同步。
  • 回饋只用愛心變色（粉紅實心），不跳提示、不跳頁。
  • 用字一律「收藏」，不要用「加入書櫃」（書櫃是已購的地方，會被誤會成購買）。

2.5 排序與篩選的分工

狀態類條件（已讀／未讀、作品型態）一律走篩選，不做成排序。書櫃的排序只排時間軸；找漫畫的排序是人氣與價格的名次。日後要加排序先問一句「這是名次或時間軸，還是狀態？」是狀態就加進篩選。
  • 排序標籤要寫明方向：价格由低到高，不要只寫「價格」讓人猜。
  • 不做標題排序：中文沒有讀者共用的字序，瀏覽器實際是依筆畫排，找不到書。
  • 找漫畫的價格排序一律比單次購買的最低金額（連載＝每話價、單卷＝單本價、多卷＝最便宜那一冊），否則混合單位會把連載全排到前面。

2.6 成功與失敗的回饋

  • 成功用浮層提示（toast）：畫面上方的膠囊，數秒後淡出。比照遊戲站的「已複製禮包碼」。
  • 失敗留在欄位旁邊（粉紅色說明文字），讓人知道是哪一格出錯。
  • 收藏例外：只變愛心顏色，不跳提示。

2.8 其他共通規則

  • 首屏以外的封面一律 loading="lazy" ＋ decoding="async"；封面 alt 寫「<作品名> 封面」。
  • 找漫畫的結果數要能被讀螢幕器播報（role="status" aria-live="polite"）。
  • 行動版點擊不要出現藍色色塊（-webkit-tap-highlight-color:transparent）。
  • 橫滑卡列與標籤列支援滑鼠按住拖曳，拖超過 6px 才啟動。

3.4 返回與導覽堆疊

  • 返回＝導覽堆疊逐層回退，每一層保存狀態快照（捲動位置、篩選條件、作品頁的擁有與進度狀態）。
  • 由底部導覽跳轉時清空堆疊；逐層下鑽的頁面（會員中心 → 歷史紀錄）不清空，返回兩次會依序退回。
  • 從作品頁進條款頁，返回會回到同一部作品的同一個狀態。
  • 通知的作品深連結會先清空堆疊、再 push 進入前的分頁，所以從排行榜開通知、看完作品頁按返回會回到排行榜。
沒有落地頁的入口不要放；入口的文案要和實際位置對得上（例：兌換碼目前在會員中心，通知文案就不能寫「到充值中心兌換」）。

4.2 找漫畫

全站作品只有這一頁可以逐一瀏覽。三條路進來看到的是同一頁：底部導覽的「找漫畫」、右上放大鏡搜尋、點任何一個標籤。差別只在最上面有沒有多一列目前的條件。

版面

  • 2 欄網格、一頁 12 筆，真實分頁。封面右上有收藏愛心。
  • 工具列捲動時固定在頂端：左為篩選（右上角數字＝已選條件數），右為排序。
  • 套用搜尋或篩選後，最上面出現結果列：顯示目前條件與符合的件數，右側的叉可清除搜尋詞。

搜尋

  • 比對標題／作者／標籤三個欄位，不分大小寫、部分比對（包含即命中），開頭的 # 會被忽略。
  • 結果數是真的算出來的，並記住最近搜尋過的詞（上限 6 筆、最新在上、去重）。
  • 點標籤＝以該標籤為關鍵字送出搜尋，也會寫進最近搜尋。

4.3 排行榜

  • 資料建議由後台統計，反映真實數據。
  • 兩層切換：期間（日／週／月，預設日）× 分類（綜合／單行本／連載）。
  • 第 1 名用全寬大卡（16:10 封面＋底部漸層，左下大數字 1、左上促銷角標）；第 2 名起是三欄網格，取 12 筆剛好 4 整列。
  • 網格內只放封面、名次大字、狀態小標、標題、價格。不放作者、標籤、漲跌、收藏愛心。
  • 由底部導覽或首頁「完整排行」進來一律重設成「日 ＋ 綜合」；從作品介紹頁返回則保留原本的選擇。
  • 建議規則：分類作品數不足 9 部（3 整列）就不開該分類。

價格規則

  • 各冊／各話可以不同價：聚合處顯示「起」、列表顯示各自價格；購買列已指定第幾冊時顯示該冊的實際價格，不用「起」。
  • 整套／整部價＝各單位實價加總後再打折。
  • 已全數擁有時不顯示價格；部分擁有時顯示「已購 N 冊／話，其餘 M 冊／話可補購」。

支付區塊整塊變暗，平台幣旁邊出現「余额不足」標籤，下一行標出還差多少（粉紅色）。「確認購買」停用，只剩「平台幣充值」可以按。金額仍然照算，讓讀者知道要補多少。充值完成後回到同一筆購買。

購買成功

說明用掉哪一張券、折抵多少，底下兩個出口：開始閱讀 或 回作品頁。 付款完成當下同時發生三件事：作品寫入書櫃的「已購」、歷史紀錄多一筆消費、用掉的那張券從帳號扣除。

退款聲明固定在彈窗底部：規則要出現在付錢的那一刻，不是只躺在條款頁。實際文案待法務定案。

從彈窗點條款／退款政策

點了會先把彈窗收起、開條款頁；條款頁的「返回」要回到原本那一筆購買——重新打開確認購買彈窗，連已經選好的優惠券（含「不使用優惠券」）都要帶回來，不可以把人丟回作品介紹頁從頭再來。

若使用者不是按返回、而是從底部導覽離開條款頁，那筆購買就放掉，之後不該莫名其妙跳出彈窗。

4.7 書櫃

三個分頁收的東西不同：續讀是還沒讀完的、已購是買過的、收藏只是加過愛心、不一定買過。 一個作品一格，多卷作品也只佔一格。每個分頁的標籤帶即時數字，分頁列捲動時固定在頂端。

續讀分頁

  • 橫式大卡：封面 ＋ 標題 ＋ 第 2 冊 / 既刊 4 冊　50% ＋ 進度條 ＋ 右側「續看」。
  • 排序固定最近閱讀由新到舊，沒有工具列。
  • 最上面一行提示「接着上次的进度继续看」——只有續讀分頁有這一行。
  • 單卷單行本顯示 单本买断 阅读中，進度條用 0／50／100% 表示未讀／閱讀中／已讀完。
  • 「續看」＝先開作品頁再開閱讀器，退出閱讀器落在作品頁、再返回才回書櫃。
  • 點卡片其他地方＝進作品頁。

已購分頁

  • 2 欄網格。封面底部深色條：左邊擁有量、右邊閱讀狀態。
  • 擁有量三種：單卷＝单本买断；多卷＝已购 N / M 册；連載＝已解锁 N / M 话（含免費話）。
  • 閱讀狀態：未读 ／ 已读 N 册（话） ／ 已读完（綠字）。
  • 作者後面接 · 更新 MM/DD：只有連載與既刊未完結的單行本顯示，完結作品不會再更新所以不顯示。

收藏分頁

卡片＝封面＋狀態角標＋標題＋作者＋價格，節奏與找漫畫列表一致。封面右上角實心愛心＝一鍵取消收藏，與作品頁雙向同步。

續讀的判定規則

  • 進入續讀：已開始閱讀（進度 > 0）且還沒把擁有的內容讀完。
  • 讀完的作品退出續讀、留在已購（標示「已讀完」），避免續讀列被已看完的作品塞滿。
  • 連載更新新話、多卷出新刊時會自動回到續讀列。
  • 買了但一頁都沒開的作品不進續讀，只在已購。
  • 「續看」開到哪一話／冊：沒讀過→第一個擁有的；目前這一個沒讀完→續看目前這一個；讀完且下一個已擁有→下一個；讀完但下一個要付費→停在目前這一個。

5優惠券與兌換碼

兌換碼是「取得」的入口，優惠券是「使用」的資產。兩者分開放：兌換碼在會員中心獨立一區，優惠券在結帳頁選用。
兌換碼優惠券
它是什麼一串字，用來取得東西帳號裡已經持有的資產
來源活動、禮包、客服補償兌換碼、活動自動發放、消費回饋
在哪裡用會員中心（輸入一次）結帳頁（每次購買時選用）
有沒有代碼有，就是它本身沒有
用完之後失效，內容進帳號從帳號扣除一張

遊戲站的「遊戲禮包碼」要給一串可複製的碼，是因為它在遊戲客戶端那個另一個系統裡消耗；漫畫館的券和結帳在同一個系統裡，所以直接勾選使用。

5.1 會員中心「我的優惠券」

  • 純清單、不可點。每張券標適用範圍（單本買斷／全站…）與有效期限，標題右側顯示「N 張可用」。
  • 底下一行說明：優惠券放在帳號裡，結帳時於「確認購買」頁勾選，系統會預設帶入折最多的一張。

5.2 會員中心「兌換碼」

  • 輸入框 placeholder：输入礼包／活动兑换码，右邊一顆「兑换」。
  • 說明：兌換成功後，平台幣或優惠券會直接進入您的帳號。
  • 成功：畫面上方浮出提示列出這次拿到什麼（數秒後淡出），券張數與餘額同時變，並補一筆「贈送」進歷史紀錄。
  • 原型在輸入框下方放了一條示範用兌換碼（JSMH2026COMIC，點一下自動填入）方便測試成功的提示，上線移除。
  • 失敗（代碼無效、已過期、已使用過）：輸入框下方出現粉紅色提示，停在原地。

5.3 券的適用判斷

「可用」＝購買類型對得上，而且實際折得到錢。滿額券沒到門檻時根本不列出來，不是列出來但不能點。

券的規則必須機器可讀（打折／定額、折抵上限、門檻、適用的購買 scope、有效期限），詳細欄位見《技術規格》。 折抵金額一律由後端重算，前端算的只拿來顯示。

6前端實作備忘

6.1 反覆踩到的 CSS 陷阱

  1. class 撞名：單檔＋全域 CSS，新增 class 前一定要先搜尋全檔。踩過兩次（.dhead 撞到搜尋下拉、.more 撞到「更多 ›」連結）。 各頁用前綴：書櫃 sh、會員中心 mc、歷史紀錄 hs、條款 lg、年齡彈窗 ag、頁尾 foot-、結帳券 cp-。
  2. 後代選擇器權重蓋過單一 class：.agegate p（0,1,1）會蓋掉 .ag-warn（0,1,0），要寫成 .agegate p.ag-warn。
  3. z-index 相同時由 DOM 順序決勝：見 2.7。驗收時用 elementFromPoint() 實際點一下，不要只斷言數值。
  4. scrollIntoView 會把整個手機外框捲走：overflow:hidden 只擋使用者捲動、不擋程式設定 scrollTop。自己算位置只設內層容器的捲動量。
  5. var 的賦值不會提升：共用資料（收藏、圖示）必須宣告在第一次渲染之前。
  6. [hidden] 失效：若外層骨架被移除，要自己補一條 [hidden]{display:none!important}。驗收時斷言 getComputedStyle(el).display，不要斷言 el.hidden（那永遠是 true）。

6.2 其他

  • 點卡片開作品頁用全域委派，排除清單要含收藏愛心，否則點愛心會順便開作品頁。
  • 彈窗內重繪要保留卷動位置。
  • 標題列是 flex：標題負責省略、NEW 標固定不縮。用文字比對找卡片時記得先去掉結尾的 NEW。
  • 篩選 chip 用 data-* 比對，不要比 textContent（通知的篩選深連結也走這條）。
