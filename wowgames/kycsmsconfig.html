1需求目的

目前 KYC 人工审核拒绝后，缺少主动告知用户的短信渠道。本次于后台「KYC配置」新增「KYC短信配置」功能，让营运人员可自行：

  • 开关「人工 KYC 审核拒绝时是否发送短信」；
  • 自行编辑发送予用户的短信内容。

藉此提升 KYC 审核不通过时对用户的告知效率，并将短信触发与内容的控制权交由营运端管理。

示意图设计说明（对照现行后台）：
  • 既有「站内信相关配置」每则讯息为「标题＋内容」双栏；KYC短信配置仅有「内容」、无「标题」——因短信无主旨栏位，此为刻意差异。
  • 既有「KYC验证结果站内信开关」是站内信整区总开关（同时管控通过／拒绝／补件站内信）；本次新增的「KYC短信不通过短信」仅针对「拒绝」情境发送短信，与既有开关各自独立、互不影响。

2.3　规则说明

① 「KYC短信配置」区块　新增

  • 区块位于「站内信相关配置」与「EKYC提交信息配置」之间。（对应 2.1）
  • 区块由上至下依序显示两个项目：「KYC短信不通过短信」开关、「KYC短信内容」输入框（含「保存」按钮）。

② 「KYC短信不通过短信」开关　新增 （对应规范 3.1.7 开关状态说明）

  • 预设关闭。
  • 开关切换即时生效，无需点击保存；切换成功后显示对应提示（见 ④ 操作提示）。
  • 开启前（关闭）：人工 KYC 审核拒绝时，不发送短信。
  • 开启后：当人工 KYC 审核结果为「拒绝」时，系统即发送「KYC短信内容」所设定的短信予该用户。
  • 本开关仅作用于「人工审核拒绝」情境；对审核通过、审核中、系统／自动判定等其他 KYC 状态不产生任何作用。

③ 「KYC短信内容」输入框 + 「保存」按钮　新增 （对应规范 3.1.2 长度、3.1.6 输入限制）

  • 多行文字输入框，可编辑，无字数限制；纯文字，不支援变量／参数占位符。
  • 预设留空，由营运人员自行填写。
  • 内容更新后须点击「保存」才会生效；未点击「保存」即离开或刷新页面，变更不会保存。
  • 「保存」按钮仅保存「KYC短信内容」，不含开关状态（开关为即时生效）。
  • 输入内容超出输入框可视高度时，输入框内出现纵向滚动条，不撑高版面。

⑤ 短信发送供应商 （依赖既有「短信相关配置」设定）

  • KYC 拒绝短信的发送供应商，依据「后台 > 系统管理 > 系统参数管理 > 短信相关配置」中所勾选的「营销短信供应商」发送。
  • 本功能不自行指定供应商，跟随上述设定；若「营销短信供应商」被变更，KYC 拒绝短信亦随之改由新供应商发送。
  • 采用的是「营销短信供应商」，而非「OTP短信供应商」。
  • 该「短信相关配置」设定本身非本次范围、不异动。

3情境穷举与判断逻辑 （对应规范 3.1.8 / 注意事项 2、4）

3.1　发送判断逻辑表：开关状态 × KYC 审核情境

KYC短信不通过短信开关KYC 审核情境是否发送短信说明
关闭（预设）人工审核 — 拒绝否开关未开启，任何情境皆不发送。
关闭（预设）人工审核 — 通过否—
关闭（预设）审核中 / 系统自动判定 / 其他状态否—
开启人工审核 — 拒绝是触发发送，内容取「KYC短信内容」当前已保存值。
开启人工审核 — 通过否本功能仅针对「拒绝」情境。
开启审核中 / 系统自动判定 / 其他状态否非「人工审核拒绝」，不触发。

3.2　内容生效逻辑表：编辑 × 保存

用户操作是否已点击保存生效结果
编辑内容后点击「保存」是新内容生效，后续发送采用新内容。
编辑内容后未点击「保存」即离开 / 刷新否变更丢弃，仍采用上一次已保存内容。
未做任何编辑—维持现有已保存内容。

3.3　边界情境：开关开启但「短信内容」为空

开关状态短信内容KYC 审核情境是否发送短信
开启为空（未填写）人工审核 — 拒绝否
开启已填写内容人工审核 — 拒绝是
规则定案：功能开启时，若「KYC短信内容」为空，当人工审核拒绝时仍不发送短信（不发送空白短信）。即「开关开启」与「内容非空」须同时成立才会触发发送。

3.4　发送触发流程

人工 KYC 审核 → 结果 = 拒绝？ 是 → 开关 = 开启？ 是 → 短信内容非空？ 是 → 发送短信予用户
（经「营销短信供应商」）
上述任一判断为「否」 → 不发送短信

4变更分类与既有规则清单 （对应注意事项 1）

4.1　新增 A

  • 「KYC短信配置」区块（位于站内信相关配置与 EKYC 提交信息配置之间）。
  • 「KYC短信不通过短信」开关（预设关闭、即时生效）。
  • 「KYC短信内容」输入框（无字数限制、纯文字、预设留空）与「保存」按钮。
  • 人工 KYC 审核拒绝时依开关发送短信的触发逻辑。

4.2　异动 M

  • 「KYC配置」页面版面：因插入新区块，站内信相关配置与 EKYC 提交信息配置之间的排版位置随之下移（内容本身不变）。

4.3　不异动（本次未涉及之既有规则）—

  • 站内信相关配置区块的内容与逻辑（含「KYC验证结果站内信开关」总开关，及通过／拒绝／补件三则站内信的标题与内容）；与本次新增之短信功能各自独立。
  • EKYC 提交信息配置区块的内容与逻辑。
  • KYC 人工审核流程、审核状态判定本身。
  • 既有站内信 / 邮件 / App 推播等其他通知机制。
  • 短信发送通道（SMS Gateway）本身的串接与设定。
  • 「短信相关配置」之「营销短信供应商 / OTP短信供应商」设定：本功能依据「营销短信供应商」发送，但仅为依赖引用，不修改该设定。
  • KYC 各状态（未验证 / 未通过 / 验证中 / 通过 / 补充资料）于前台的显示规则。
